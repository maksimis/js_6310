Node.js

  • Среда выполнения JS вне браузера на движке V8
  • Событийная неблокирующая I/O — тот же Event Loop
  • Где используется: серверы, утилиты, инструменты сборки
  • npm — крупнейший реестр пакетов (альтернатива — Yarn)
Повторение JS

Всё, что вы уже знаете

  • let/const, undefined vs null
  • function expression и стрелочные функции (полная и сокращённая)
  • Замыкания и каррирование
  • Классы: extends, super

В Node используется ровно тот же JavaScript — без браузера.

Установка

  • Сайт nodejs.org → LTS-версия
  • npm устанавливается вместе с Node
  • Проверка: node --version, npm --version
  • Рекомендация: менеджер версий nvm (для разных версий Node)

Основы npm

  • npm init -y — новый проект; npm init es6 -y — с ES-модулями
  • npm install / --save-dev / -g
  • npm uninstall, npm update
  • npx — запуск пакета без установки: npx cowsay

Структура приложения

Модули: CommonJS vs ES6

utils/math.js (CommonJS)

module.exports = {
    sum: (a, b) => a + b,
    multiply: (a, b) => a * b
};

utils/math.js (ES6)

export function sum(a, b) {
    return a + b;
}
export function multiply(a, b) {
    return a * b;
}

ES6-модули включаются полем "type": "module" в package.json.

Тестирование

  • Юнит- и интеграционные тесты
  • Jest (популярный) vs Mocha + Chai
  • Польза: ранние ошибки, безопасный рефакторинг, документация поведения
  • npm i -D jest + скрипты test/test:watch/test:coverage
Jest

describe · test · expect

tests/math.test.js

import * as math from '../src/utils';
import { describe, test, expect } from '@jest/globals';

describe('Math module', () => {
    test('sums two numbers correctly', () => {
        expect(math.sum(2, 3)).toBe(5);
    });
    test('multiplies two numbers correctly', () => {
        expect(math.multiply(2, 3)).toBe(6);
    });
    test('sum handles negative numbers', () => {
        expect(math.sum(-1, -2)).toBe(-3);
    });
});
  • describe группирует, test — случай, expect(...).toBe(...) — проверка

    • Практика: Telegram-бот

    src/index.js

    import TelegramBot from 'node-telegram-bot-api';
import dotenv from 'dotenv';

dotenv.config();
const token = process.env.TELEGRAM_BOT_TOKEN;

const bot = new TelegramBot(token, { polling: true });

bot.onText(/\/start/, (msg) => {
    bot.sendMessage(msg.chat.id, 'Привет! Я твой первый бот!');
});

bot.on('message', (msg) => {
    if (msg.text !== '/start') {
        bot.sendMessage(msg.chat.id, `Вы сказали: "${msg.text}"`);
    }
});

    Токен — через BotFather; хранить в .env, читать через dotenv.

    Telegram-бот

    BotFather · webhook vs polling

    • BotFather — создание бота и получение токена в Телеграме
    • Polling — бот сам опрашивает сервер (просто, без сервера)
    • Webhook — Telegram сам шлёт события на URL (нужен сервер)
    • nodemon — авто-перезапуск при изменении кода
    • Polling — наглядная демонстрация событийного цикла из темы 4
    Mocking

    jest.fn() · jest.mock()

    import TelegramBot from 'node-telegram-bot-api';

jest.mock('node-telegram-bot-api');   // заменяем библиотеку моком

const mockSend = jest.fn();
TelegramBot.mockImplementation(() => ({
    onText: jest.fn(),
    on: jest.fn(),
    sendMessage: mockSend
}));

test('бот отвечает на /start', async () => {
    require('../src/index');
    expect(TelegramBot).toHaveBeenCalledWith(expect.anything(),
        { polling: true });
});
    • mockResolvedValue — замок ответа промиса для async/await
    • Интеграционный тест бота проверяет, что onText вызван

    ESLint 2026

    eslint.config.js (flat config)

    8_eslint/eslint.config.js

    import js from "@eslint/js";
import globals from "globals";
import { defineConfig } from "eslint/config";

export default defineConfig([
  {
    files: ["**/*.{js,mjs,cjs}"],
    plugins: { js },
    extends: ["js/recommended"],
    languageOptions: { globals: globals.node }
  },
]);

    Скрипты в package.json:

    "lint": "eslint .",
"lint:fix": "eslint . --fix"

    Правила: indent, quotes, semi, no-unused-vars, no-console, prefer-const, eqeqeq.

    Рабочий процесс

    Сборка → тесты → линтер → CI

    1. Сборка — npm-скрипты: start / dev
    2. Тесты — Jest: юнит + интеграционные (мок бота)
    3. Линтер — ESLint: единый стиль и ранние ошибки
    4. CI — то же самое на сервере при каждом PR

    Этот же процесс ждёт вас в React-проектах тем 8–12.
