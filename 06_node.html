Node.js

  • Среда выполнения JS вне браузера на движке V8
  • Событийная неблокирующая I/O — тот же Event Loop
  • Где используется: серверы, утилиты, инструменты сборки
  • npm — крупнейший реестр пакетов (альтернатива — Yarn)
Повторение JS

Всё, что вы уже знаете

  • let/const, undefined vs null
  • function expression и стрелочные функции (полная и сокращённая)
  • Замыкания и каррирование
  • Классы: extends, super

В Node используется ровно тот же JavaScript — без браузера.

Установка

  • Сайт nodejs.org → LTS-версия
  • npm устанавливается вместе с Node
  • Проверка: node --version, npm --version
  • Рекомендация: менеджер версий nvm (для разных версий Node)

Основы npm

  • npm init -y — новый проект; npm pkg set type=module — включить ES-модули
  • npm install / --save-dev / -g
  • npm uninstall, npm update
  • npx — запуск пакета без установки: npx cowsay "Hello, Node.js!"

{

  • scripts — команды проекта: npm run dev, npm test
  • dependencies — нужны при работе, devDependencies — только при разработке
  • node --watch перезапускает программу при изменении файлов — nodemon не нужен
  • Jest и ES-модули: флаг --experimental-vm-modules и "transform": {}, иначе тесты не запустятся
Структура приложения

Модули: CommonJS vs ES6

utils/math.js (CommonJS)

module.exports = {
    sum: (a, b) => a + b,
    multiply: (a, b) => a * b
};

utils/math.js (ES6)

export function sum(a, b) {
    return a + b;
}
export function multiply(a, b) {
    return a * b;
}

ES6-модули включаются полем "type": "module" в package.json. В импорте обязательно расширение: import { sum } from './utils/math.js' — без .js Node выдаст ERR_MODULE_NOT_FOUND.

Jest

describe · test · expect

06_node/6_jest/tests/math.test.js

import * as math from '../src/utils/index.js';
import { describe, test, expect } from '@jest/globals';

describe('Math module', () => {
    test('sums two numbers correctly', () => {
        expect(math.sum(2, 3)).toBe(5);
    });
    test('multiplies two numbers correctly', () => {
        expect(math.multiply(2, 3)).toBe(6);
    });
    test('sum handles negative numbers', () => {
        expect(math.sum(-1, -2)).toBe(-3);
    });
});
  • describe группирует, test — случай, expect(...).toBe(...) — проверка

    Telegram-бот

    06_node/8_eslint/src/bot.js

    // src/bot.js — логика отдельно от запуска, чтобы её можно было протестировать
import TelegramBot from 'node-telegram-bot-api'

export function createBot(token) {
    if (!token) throw new Error('Не задан TELEGRAM_BOT_TOKEN')

    const bot = new TelegramBot(token, { polling: true })

    bot.onText(/\/start/, (msg) => {
        bot.sendMessage(msg.chat.id, 'Привет! Я твой первый бот!')
    })
    bot.on('message', (msg) => {
        if (msg.text !== '/start') {
            bot.sendMessage(msg.chat.id, `Вы сказали: "${msg.text}"`)
        }
    })
    return bot
}

    06_node/8_eslint/src/index.js

    // src/index.js — точка входа
import dotenv from 'dotenv'
import { createBot } from './bot.js'

dotenv.config()                          // .env -> process.env
createBot(process.env.TELEGRAM_BOT_TOKEN)

    Токен — у @BotFather. В репозиторий кладём .env.example без значения, а сам .env — в .gitignore. Без dotenv: node --env-file=.env src/index.js (Node ≥ 20.6).

    Telegram-бот

    BotFather · webhook vs polling

    • BotFather — создание бота и получение токена в Телеграме
    • Polling — бот сам опрашивает сервер (просто, без сервера)
    • Webhook — Telegram сам шлёт события на URL (нужен сервер)
    • node --watch — авто-перезапуск при изменении кода
    • Polling — наглядная демонстрация событийного цикла из темы 4
    Mocking

    Мок модуля в ES-модулях

    06_node/8_eslint/tests/bot.test.js (сокращено)

    import { jest, test, expect } from '@jest/globals'

const sendMessage = jest.fn()
const handlers = { onText: [] }
const TelegramBot = jest.fn().mockImplementation(() => ({
    onText: (regexp, cb) => handlers.onText.push([regexp, cb]),
    on: jest.fn(),
    sendMessage,
}))

// в ESM jest.mock() не поднимается над import — мокаем ДО импорта бота
jest.unstable_mockModule('node-telegram-bot-api', () => ({ default: TelegramBot }))
const { createBot } = await import('../src/bot.js')

test('отвечает на /start', () => {
    createBot('test-token')
    const [, onStart] = handlers.onText[0]

    onStart({ chat: { id: 42 }, text: '/start' })
    expect(sendMessage).toHaveBeenCalledWith(42, 'Привет! Я твой первый бот!')
})
    • jest.fn() — функция-шпион: запоминает вызовы и аргументы
    • Мок заменяет настоящую библиотеку: тест не ходит в Telegram и не нужен токен
    • mockResolvedValue — мок ответа промиса для async/await

    ESLint

    • Статический анализ: единый стиль, ошибки до запуска
    • Создать конфиг: npm init @eslint/config@latest; исправить автоматически: eslint . --fix

    ESLint 2026

    eslint.config.js (flat config)

    06_node/8_eslint/eslint.config.js

    import js from "@eslint/js";
import globals from "globals";
import { defineConfig } from "eslint/config";

export default defineConfig([
  {
    files: ["**/*.{js,mjs,cjs}"],
    plugins: { js },
    extends: ["js/recommended"],
    languageOptions: { globals: globals.node }
  },
]);

    Скрипты в package.json:

    package.json

    "lint": "eslint .",
"lint:fix": "eslint . --fix"

    Правила качества: no-unused-vars, prefer-const, eqeqeq, no-console. Форматирование (отступы, кавычки, точки с запятой) в ESLint 9 вынесено в @stylistic/eslint-plugin — или используйте Prettier.

    Рабочий процесс

    Сборка → тесты → линтер → CI

    • Сборка — npm-скрипты: start/dev
    • Тесты — Jest: юнит + интеграционные (мок бота)
    • Линтер — ESLint: единый стиль и ранние ошибки
    • CI — то же самое на сервере при каждом PR

    Этот же процесс ждёт вас в React-проектах тем 8–12.

    CI

    GitHub Actions: проверка каждого PR

    .github/workflows/ci.yml

    # .github/workflows/ci.yml
name: CI
on: [push, pull_request]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 24
      - run: npm install      # npm ci — если package-lock.json лежит в репозитории
      - run: npm run lint
      - run: npm test

    Если линтер или тесты упали — PR помечается красным, и ошибку видно до ревью.
